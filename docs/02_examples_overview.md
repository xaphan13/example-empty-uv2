# Обзор примеров и как их запускать

## Как запускать примеры

Каждый пример можно запускать отдельно через модуль или через главный скрипт `main.py`.

### Через главный скрипт

Запуск всех примеров последовательно:
```bash
python main.py
```

### Через конкретные модули

Каждый пример имеет свою точку входа:

#### Многопроцессорные приложения
```bash
python -m ex_work_process.main_work_process
```

#### Простой async/await
```bash
python -m ex_async_simple.main_async_simple
```

#### Async context managers
```bash
python -m ex_async_with.main_async_with
```

#### Async генераторы и итераторы
```bash
python -m ex_async_gen_iter.main_async_gen_iter
```

#### Метаклассы
```bash
python -m ex_metaclass.main_metaclass
```

#### Работа с библиотеками
```bash
python -m ex_library.main_library
```

#### Работа с ZIP архивами
```bash
python -m ex_file_zip.main_file
```

#### Алгоритмические задачи
```bash
python -m ex_code_war.main_code_war
```

#### Различные другие примеры
```bash
python -m ex_all_others.main_others
```

#### GUI на CustomTkinter + pygubu
```bash
python -m ex_window_app_customtkinter.main_window_app
```

Headless-проверки (без открытия окна):
```bash
python -m ex_window_app_customtkinter.main_window_app --smoke [имя_примера]
python -m ex_window_app_customtkinter.main_window_app --smoke-window [секунды]
```

#### GUI на PySide6 (Qt6)
```bash
python -m ex_window_app_pyside6.main_window_app
```

Headless-проверки (без дисплея, через платформенный плагин Qt):
```bash
QT_QPA_PLATFORM=offscreen python -m ex_window_app_pyside6.main_window_app --smoke
QT_QPA_PLATFORM=offscreen python -m ex_window_app_pyside6.main_window_app --smoke-window 3
```

> Замечание: обычный запуск открывает окно и блокирует терминал до закрытия.
> GUI-примеры намеренно не включены в `main.py` (окно заблокировало бы прогон).

## Краткое описание каждого примера

### ex_work_process
Демонстрирует различные подходы к многопроцессорному программированию в Python:
- Прямое использование `multiprocessing.Process`
- Использование `multiprocessing.Pool`
- Использование `concurrent.futures.ProcessPoolExecutor`
- Комбинированные пулы процессов

### ex_async_simple
Примеры базового асинхронного программирования:
- Простые корутины с `async/await`
- Использование `asyncio.gather()` для запуска нескольких корутин
- Работа с контекстными переменными в асинхронном контексте

### ex_async_with
Примеры использования асинхронных контекст-менеджеров:
- Создание и использование собственных async context managers
- Работа с асинхронными ресурсами (например, сетевые соединения)

### ex_async_gen_iter
Асинхронные генераторы и итераторы:
- Создание асинхронных генераторов с `async yield`
- Использование `async for` для итерации по асинхронным последовательностям
- Обработка исключений в асинхронных генераторах

### ex_metaclass
Создание и использование метаклассов:
- Пользовательские метаклассы для модификации создания классов
- Метаклассы, которые вызывают себя多次
- Переопределение специальных методов через метаклассы
- Переменные, определенные внутри функций в контексте метаклассов

### ex_library
Работа с внешними библиотеками:
- Потоковая обработка данных с использованием `streamz`
- Создание пользовательских потоковых преобразований
- Примеры интеграции различных потоковых операций

### ex_file_zip
Работа с ZIP архивами без создания временных файлов:
- Создание ZIP архивов в памяти
- Чтение и извлечение файлов из ZIP архивов
- Обработка ZIP архивов без промежуточного сохранения на диск

### ex_code_war
Алгоритмические задачи и кодварс-стильные примеры:
- Проверка правильности скобочных последовательностей
- Разделение строк по различным критериям
- Демонстрация операций с `__iadd__` и связанными методами

### ex_all_others
Различные полезные примеры и техники:
- Работа с ловушками и обработкой исключений (`trap_task`)
- Использование SSH туннелей (`ssh1`)
- Примеры работы с байт-кодом и дисассемблированием (`dis_module`, `dis_async_await`)
- Форматированный вывод в терминал с `rich`
- Демонстрация замыканий и их применения (`closure_func`)
- Глубокое копирование объектов (`deep_copy_example`)
- Работа с хешированием и проверкой целостности (`sobes11`)
- Различные утилиты и вспомогательные функции (`others_11`, `my_module`)
- Работа с глобальными переменными и модулями (`glob_mod`)
- Работа с диспатчерами и обработчиками событий

### ex_window_app_customtkinter
Оконное GUI-приложение на базе `CustomTkinter` (CTk-виджеты поверх Tkinter) с
тёмной темой и контрастной палитрой Tokyo Night; интерфейс загружается из
`.ui`-файла Pygubu (`window_app.ui`) через плагин `pygubu.plugins.customtkinter`,
точка входа — `../ex_window_app_customtkinter/main_window_ctk.py`:
- Раскладка (окно 900×600): **сайдбар слева** с заголовком «Примеры», полем
  поиска, счётчиком «Найдено: N из 5» и `CTkScrollableFrame` со списком из 5
  карточек-примеров; **контент справа** заполнен секциями сверху вниз —
  шапка выбранного примера (крупный заголовок + описание), панель опций
  (свитчи «Очистка перед запуском», «Автопрокрутка вывода»), ряд из трёх
  мини-карточек-метрик («Примеров в реестре», «Последний запуск», «Статус»),
  панель вывода («терминал», моноширинный шрифт), панель кнопок
  («Запустить» — акцентная, «Очистить», «Копировать»), прогресс-индикатор и
  статусная строка.
- Выбор примера — кликом по карточке в сайдбаре: выбранная карточка
  подсвечивается акцентным бордюром, шапка контента обновляется; комбобокс
  выбора не используется.
- Тема фиксируется в коде: `ctk.set_appearance_mode("Dark")` +
  `ctk.set_default_color_theme("blue")`; цвета виджетов заданы явно
  (акцент `#7aa2f7`, панели `#292e42`, терминал `#101017`); переключатель
  тем не предусмотрен.
- Запуск курируемых примеров проекта (`ex_async_simple`, `ex_code_war`,
  `ex_file_zip`, `ex_metaclass`, `ex_work_process`) прямо из окна: захват
  `stdout`/`stderr` и записей логирования в текстовое поле
  (`example_runner.run_example`).
- Запуск примера в фоновом потоке с прогресс-индикатором и доставкой
  вывода в UI через очередь (`threading` + `queue` + `window.after`);
  поведение настраивается свитчами (очистка перед запуском, автопрокрутка).
- Headless-режимы для проверок:
  - `--smoke [имя]` — без создания окна вызывает раннер и печатает
    захваченный вывод в stdout (для qa-пачек curl-стиля);
  - `--smoke-window [сек]` — собирает окно и закрывает его через N секунд,
    используется под `xvfb-run` для полного smoke без ручного закрытия.
- Не входит в пакетный запуск `main.py` — открытое окно заблокировало бы
  общий прогон.

### ex_window_app_pyside6
Минимальное оконное приложение на `PySide6` (Qt6) — тот же класс задачи, что и
`ex_window_app_customtkinter`, но на другом стеке (дублирование примеров «одна
задача — разные подходы» в проекте приветствуется). Точка входа —
`../ex_window_app_pyside6/main_window_pyside.py`:
- Разметка собирается только кодом (без `.ui`-файлов и pygubu), класс окна —
  `ApplicationWindow(QWidget)` в `ex_window_app_pyside6/application_window.py`.
- Состав окна ровно по заданию: два поля ввода (`QLineEdit` — «Имя» и
  «Сообщение»), две кнопки (`QPushButton` — «Показать» и «Очистить») и метка
  результата (`QLabel`).
- Поведение: «Показать» пишет в метку строку `«<имя>: <сообщение>»`, при обоих
  пустых полях — «Введите имя и сообщение»; «Очистить» очищает поля и метку.
- Логирование через `config_log` не подключается — пример демонстрирует только Qt.
- Headless-режимы (дисплей не нужен — используется платформенный плагин
  `offscreen`, входящий в поставку PySide6):
  - `--smoke` — собирает окно, проверяет наличие виджетов по `objectName`,
    печатает `smoke ok` и завершается с кодом 0, окно не показывается;
  - `--smoke-window [сек]` — показывает окно и закрывает его через N секунд
    (по умолчанию 5), код возврата 0.
- Обычный запуск без флагов открывает окно с заголовком «PySide6 — пример окна».
- На Linux (Ubuntu/Debian) для обычного запуска нужен системный пакет
  `libxcb-cursor0` (`sudo apt install libxcb-cursor0`) — см. «Требования к запуску».
  Headless-режимы `offscreen` работают без него.
- Не входит в пакетный запуск `main.py` — открытое окно заблокировало бы
  общий прогон.

## Требования к запуску

Для запуска всех примеров необходимы:
- Python 3.12 или выше
- Установленные зависимости из `pyproject.toml` (выполнить `uv sync`)
- Для некоторых примеров может потребоваться доступ к сети или файловой системе

### Qt-примеры на Linux (Ubuntu/Debian)

PySide6 (Qt6) для запуска окна с реальным дисплеем требует системных библиотек XCB,
которых нет в базовой поставке Ubuntu. Если при обычном запуске
`ex_window_app_pyside6` появляется ошибка
`Could not load the Qt platform plugin "xcb"`, установите недостающий пакет:

```bash
sudo apt install libxcb-cursor0
```

Остальные XCB-библиотеки (`libxcb-icccm4`, `libxcb-keysyms1`, `libxcb-shape0`,
`libxcb-xinerama0`, `libxkbcommon-x11-0`) в Ubuntu 22.04 уже стоят. Headless-режимы
(`--smoke`, `--smoke-window` с `QT_QPA_PLATFORM=offscreen`) этих библиотек не требуют,
поэтому проверки проходят и без них.

#### Проверка окна без дисплея (Xvfb)

Если дисплея нет (ssh, CI, сессия агента), окно всё равно можно поднять и увидеть —
через виртуальный X-сервер из пакета `xvfb`:

```bash
xvfb-run -a --server-args="-screen 0 1280x800x24" \
  uv run python -m ex_window_app_pyside6.main_window_app --smoke-window 3
```

Скриншот окна снимается самим Qt, без ImageMagick и `import`:

```bash
xvfb-run -a --server-args="-screen 0 1280x800x24" uv run python -c "
from PySide6.QtWidgets import QApplication
from ex_window_app_pyside6.application_window import ApplicationWindow
app = QApplication([])
w = ApplicationWindow()
w.name_input.setText('Иван')
w.message_input.setText('привет')
w.show_button.click()
w.show()
app.processEvents()
print(w.grab().save('tasks/current/screenshots/gui_test_under_xvfb.png'), w.result_label.text())
"
```

Это единственный способ проверить реальный xcb-плагин: `QT_QPA_PLATFORM=offscreen`
обходит его стороной и не поймает, например, нехватку `libxcb-cursor0`.

## Советы по изучению

Каждый пример содержит комментарии и структурированный код, который иллюстрирует конкретную концепцию. Рекомендуется:
1. Запускать пример и наблюдать вывод
2. Изучать исходный код, обращая внимание на комментарии
3. Модифицировать примеры для лучшего понимания работы механизмов
4. Сравнивать růзные подходы к решению аналогичных задач в разных директориях
