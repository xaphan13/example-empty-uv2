# Adversarial review — ex_window_app_pyside6 (PySide6/Qt6)

Сессия: прогон по заданию `tasks/current/REQUIREMENTS.md` (изменённая функциональность —
новый GUI-пример). Всё локально, headless, без сервера:

- окружение: `QT_QPA_PLATFORM=offscreen`, Python 3.12 + uv, cwd = корень проекта;
- каждая проверка обёрнута в `timeout`, чтобы ничего не зависнуть;
- код продукта не правился, `DEFECTS.md` не создавался.

Оценка ведётся по REQUIREMENTS.md (особенно критерий 7: «Некорректные аргументы дают
exit 2 без traceback»). Скриншоты не снимались: окно headless, визуального слоя нет.

Итого проверено: границы `--smoke-window` (отрицательные, нечисловые, дробные,
отсутствующее значение, огромные, inf/nan/overflow, пробелы, комплексные), конфликт
флагов, неизвестные/лишние аргументы, поведение окна на границах (пустые/пробельные
поля, длинные строки, юникод/эмодзи/HTML, повторные клики), импорт и побочные эффекты,
идемпотентность, запуск из чужого cwd, программный `main(argv)`.

## ADV-001 — `--smoke-window inf` даёт traceback вместо exit 2

- **Что делал:**
  ```bash
  QT_QPA_PLATFORM=offscreen timeout 20 uv run python -m ex_window_app_pyside6.main_window_app --smoke-window inf
  ```
- **Ожидаемый результат (REQUIREMENTS.md, критерий 7 и контракт фазы 3):** некорректное
  значение `--smoke-window` → argparse exit 2, понятное сообщение в stderr, без traceback.
- **Фактический результат:** `EXIT=1`, необработанное исключение:
  ```
  File ".../main_window_app.py", line 111, in main
      QTimer.singleShot(int(args.smoke_window * 1000), app.quit)
  OverflowError: cannot convert float infinity to integer
  ```
- **Почему удивило:** `_positive_float` проверяет `seconds <= 0`; для `inf` это `False`,
  поэтому значение проходит валидацию и падает уже на `int()` в `main()`.
- **Скриншот:** не снимался (headless offscreen).
- **Предлагаемая серьёзность:** Major (нарушение критерия 7 — traceback вместо exit 2).
- **Оценка по REQUIREMENTS.md:** нарушение контракта — да.
- **Disposition: ACCEPTED -> DEF-001**

## Проверки, завершившиеся без аномалий

- **Конфликт `--smoke --smoke-window 3`** → exit 2, stderr `Нельзя одновременно использовать --smoke и --smoke-window`; программно `main([...])` вернул `rc 2`. Соответствует спеке.
- **`--smoke-window -1`** → exit 2, `значение должно быть > 0: '-1'`. Соответствует.
- **`--smoke-window abc`** → exit 2, `не число: 'abc'`. Соответствует.
- **`--smoke-window 0.5`** → exit 0. Соответствует.
- **`--smoke-window 0.0001`** → exit 0 (таймер ~0 мс, мгновенный выход). Соответствует «> 0».
- **`--smoke-window=` (пусто)** → exit 2, `не число: ''`. Соответствует.
- **`--smoke-window -inf`** → exit 2, `unrecognized arguments: -inf`. Соответствует.
- **`--smoke-window " 5 "`** → exit 0; **`--smoke-window 5j`** → exit 2, `не число`. Соответствует.
- **`--smoke --bogus`** → exit 2, `unrecognized arguments: --bogus`. Соответствует.
- **`--smoke extra`** (лишний позиционный) → exit 2, `unrecognized arguments: extra`. Соответствует.
- **Поведение окна:** только имя → `'Аня: '`; только сообщение → `': привет'`; оба пусты →
  `'Введите имя и сообщение'`; длинные строки (5000+5000) → 10002 символа без сбоя;
  юникод/эмодзи/`<b>`/`&`/кавычки → выводятся буквально (не исполняются); повторные клики
  «Показать» идемпотентны; «Очистить» → поля пусты, метка `'—'`; «Очистить» на пустом окне
  стабильно; `show` после `clear` → `'Введите имя и сообщение'`. Соответствует.
- **Импорт и побочные эффекты:** импорт `main_window_app` и `application_window` →
  `QApplication.instance()` = `None`; повторный импорт возвращает тот же объект; виджеты не
  создаются. Соответствует.
- **Программный `main(["--smoke"])`** → печатает `smoke ok`, возвращает `0` типа `int`, сам
  `sys.exit` не вызывает. Соответствует.
- **Два `--smoke` подряд в одном shell** → оба exit 0, идемпотентно. Соответствует.

## Вердикт

Найдено 3 однотипных дефекта обработки граничных значений `--smoke-window`
(`inf`, `nan`, `1e309` → необработанный traceback и exit 1 вместо argparse exit 2),
нарушающих критерий 7 REQUIREMENTS.md. Остальные границы, конфликт флагов, неизвестные
аргументы, поведение окна, импорт и идемпотентность — контракту соответствуют.
Ни одна запись не PENDING по моей стороне быть не может — disposition заполняет оркестратор.
